## 2. Apple Developer Program に登録する（済み）

> 登録・有料App契約・口座・税務情報は**済み**とのことなので、この手順は飛ばしてください。下は参考です。

https://developer.apple.com/account →「**Certificates, IDs & Profiles**」→「**Identifiers**」→「＋」

## 5. 課金商品（App内課金）を作る

アプリ →「**収益化**」→「**App内課金**」→「＋」

**製品IDはゲームと1文字も違わないように**してください。種類を選ぶ画面で、プレミアムパスだけ「**非更新サブスクリプション**」を選びます（「サブスクリプション」のメニューではなく、この「App内課金」の中で作ります）。

| 種類 | 参照名 | 製品ID | 価格（日本） |
|---|---|---|---|
| **非更新サブスクリプション** | プレミアムパス30日 | `premium30d` | ¥480 |
| 消耗型 | ダイヤ10個 | `dia10` | ¥300 |
| 消耗型 | ダイヤ20個 | `dia20` | ¥500 |
| 消耗型 | ダイヤ40個 | `dia40` | ¥900 |

それぞれ：
1. **価格**：「日本」で上の金額を選ぶ（ゲーム内の表示と同じにする）。ほかの国は自動換算でOK
2. **ローカリゼーション（日本語）**
   - 表示名：「プレミアムパス（30日）」「ダイヤ×10」など
   - 説明：「30日間、QR召喚が1日20回・スタミナ上限10・広告なし。自動更新されません」「ゲーム内で使えるダイヤ10個」など
3. **審査に関する情報**：その商品の購入画面のスクリーンショットを1枚（TestFlight で撮ったものでOK。先に作って、画像はあとから追加しても大丈夫）
4. 保存

> 初めての課金商品は、**アプリと一緒に審査に出します**（手順12-3）。

## 8. Codemagic の設定

https://codemagic.io →「Sign up」→ **GitHub でログイン**

1. **アプリを追加**：「Add application」→ GitHub → `qr-summon-battle` → 種類は「Other」
2. **API キー**：「Team settings」→「Team integrations」→「Developer Portal」→「Manage keys」→「Add key」
   - 名前：`QR`（`codemagic.yaml` と同じ名前）

3. **証明書**：「Team settings」→「codemagic.yaml settings」→「Code signing identities」→「iOS certificates」
   →「Generate certificate」→ 名前 `dist`・種類 **Apple Distribution**
   - 表示される `.p12` とパスワードは**その場で1回だけ**保存できます。念のため保存。
4. **プロファイル**：
   - https://developer.apple.com/account →「Profiles」→「＋」→「Distribution」の「**App Store Connect**」
     → App ID：手順3のもの → 証明書：今作ったもの（今日の日付）→ 名前 `QR Summon AppStore` →「Generate」
   - Codemagic の「Code signing identities」→「iOS provisioning profiles」→「**Fetch profiles**」→ `QR Summon AppStore` を取り込む

## 10. TestFlight で動作確認する

### 10-1. インストール
App Store Connect → アプリ →「TestFlight」→「内部テスト」の「＋」でグループを作り、自分を追加
→ iPhone に「**TestFlight**」アプリを入れて、招待からインストール

### 10-2. 課金のテスト（お金はかかりません）
1. App Store Connect →「ユーザとアクセス」→「**Sandbox**」→ テスト用アカウントを作成
   （使っていないメールアドレスが必要。Gmail なら `名前+test1@gmail.com` の形でも可）
2. iPhone の「**設定**」→「**App Store**」→ 下の方の「**サンドボックスアカウント**」でサインイン
3. TestFlight 版で購入すると「[Sandbox]」と出て、請求されません

### 10-3. 確認リスト
- [ ] 起動時に「トラッキングの許可」が出る。「許可しない」でも遊べる
- [ ] 縦に持っても横向きのまま
- [ ] QR召喚：カメラで QRコード／バーコードが読める（初回はカメラの許可）
- [ ] 「画像から選ぶ」でも読める
- [ ] 召喚画面に「UR 2%」「SR 5%」が出ている
- [ ] ダイヤ3種が買えて、数が正しく増える（**1回の購入で2回増えない**）
- [ ] 購入画面で「キャンセル」しても何も起きない
- [ ] プレミアムパスが買えて「あと30日」になる
- [ ] **アプリを削除して入れ直す** → 起動しただけで、プレミアムパスの残り日数が戻る（自動復元）
- [ ] プレミアムパス画面の「**購入を復元する**」でも戻る
- [ ] ショップの「広告を見る」でテスト広告が出て、最後まで見ると報酬がもらえる
- [ ] プレミアムパス有効中は、広告なしで受け取れる
- [ ] 引き継ぎコードの発行・受け取り（アプリ同士）、フレンド対戦が使える
- [ ] 規約・プライバシーポリシー・特商法・資金決済法の表示が開ける
- [ ] アプリを閉じて開き直しても、データが残っている

## 11. AdMob の設定（審査に出す前に）

https://admob.google.com（Google アカウントでログイン）

1. **登録**：国・タイムゾーン・お支払い情報を入力
2. **アプリを追加**：「アプリ」→「アプリを追加」→ プラットフォーム **iOS** →「ストアに公開されていますか？」→ **いいえ**（未公開として追加）→ 名前 `QR召喚バトル`
   - **アプリID**（`ca-app-pub-数字~数字`）★
3. **広告ユニット**：「広告ユニットを追加」→「**リワード**」→ 名前 `reward` → 作成
   - **広告ユニットID**（`ca-app-pub-数字/数字`）★
4. **同意メッセージ**：「プライバシーとメッセージ」→「**GDPR**」で同意フォームを作って公開（欧州のユーザー向け。日本だけでも作っておくのがおすすめ）
5. **本番IDに差し替え**：GitHub の `codemagic.yaml` の
   - `ADMOB_APP_ID:` → アプリID ★
   - `ADMOB_REWARDED_ID:` → 広告ユニットID ★
   に書き換えて、もう一度ビルド（手順9）
   > テスト用ID のままビルドすると、ビルドログに「⚠️ AdMob はテスト用IDでビルドしています」と出ます。**審査用はこれが出ないこと**を確認してください。
6. 自分の iPhone では**本番広告をタップしない**でください（不正クリック扱いになることがあります）。

App Store Connect → アプリ →「iOSアプリ 1.0」

- このアプリは **iPhone 専用・横向き**です。必須は **6.9インチ**（**2868×1320** などの横長）。

- **プライバシーポリシーURL**：`https://in-on.github.io/qr-summon-battle/privacy.html`

- 「ビルド」の「＋」で TestFlight のビルドを選ぶ
- 「App内課金とサブスクリプション」に `premium30d` `dia10` `dia20` `dia40` を追加

### 12-4. 年齢制限・カテゴリ
- カテゴリ：ゲーム（ロールプレイング など）

## 13. 公開されたあとにやること

### 13-1. AdMob とストアを連携
AdMob →「アプリ」→ QR召喚バトル →「アプリの設定」→「**アプリストアの詳細**」→「追加」→ App Store で公開されたアプリを検索して選ぶ

### 13-2. app-ads.txt を置く
app-ads.txt は、**サイトのいちばん上**（`https://in-on.github.io/app-ads.txt`）に置く必要があります。
今のゲームは `in-on.github.io/qr-summon-battle/` の下なので、**別のリポジトリ**を作ります。

1. GitHub で「New repository」→ 名前を **`in-on.github.io`**（そのまま）にして Public で作成
2. 「Add file」→「Create new file」→ ファイル名 `app-ads.txt`
3. 中身は AdMob の「アプリ」→「すべてのアプリを表示」→「**app-ads.txt**」に表示される1行をコピーして貼る
   （`google.com, pub-数字, DIRECT, f08c47fec0942fa0` の形）
4. 「Commit changes」
5. 数分後、ブラウザで `https://in-on.github.io/app-ads.txt` を開いて、その1行が表示されればOK
6. App Store Connect の「**マーケティングURL**」に `https://in-on.github.io/` を入れる
   （AdMob はこのURLのサイトから app-ads.txt を探します）
7. AdMob の app-ads.txt の画面で「アップデートを確認」→ 1日ほどで確認済みになります

### 13-3. Web版を閉じる
Supabase の `qr_config` の `web_closed` を true にし、note に App Store のURLを入れると、ブラウザ版に「App Store で見る」が出ます。

| 課金 | StoreKit 2。Apple の署名を確認できた購入だけ true を返す。ダイヤは消耗型、プレミアムパス `premium30d` は非更新サブスクリプション |
| 購入の復元 | `QRIAP.restore()` が `premium30d` の有効な取引の購入日時（ms）の一覧を返す。起動時にも自動で `QRPremRestore(一覧)` を呼ぶ（起動時はサインインのダイアログを出さない） |
| 二重付与の防止 | ゲームが付与し終えてから取引を完了。付与済みの取引IDも記録し、同じ取引が再び届いても付与しない |
| 付与もれの防止 | 付与の前にアプリが落ちた場合は、次の起動時に1回だけ付与（プレミアムパスは購入日から期限を計算するので、二重に延びない） |
| 広告 | AdMob リワード広告。今は Google のテスト用ID |
| ATT・SKAdNetwork | 起動時にトラッキング許可を確認。SKAdNetwork は Google 公式の一覧（50件）を設定 |
| カメラ | 用途の説明文を設定。ゲーム内のカメラがそのまま使える |

### 気になる点（必要ならゲーム側で対応を検討）
1. **N の確率が表示されていません。** UR と SR だけ出ているので、「N 93%」も並べると、より確実です（index.html の変更になるので、今回は入れていません）。
